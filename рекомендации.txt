# Рекомендации по спецификации торговой стратегии
Версия: 0.1 (черновик)
Дата: __________
Область: Brent, природный газ, индекс Мосбиржи

## 1. Назначение
Документ превращает согласованные протоколы (устаревшие котировки,
геополитические события, важные публикации, ложные пробои) в
исполняемую спецификацию для торгового робота.

## 2. Инструменты и таймфреймы
- Brent
- Природный газ
- Индекс Мосбиржи

Для каждого инструмента и таймфрейма задаются отдельные параметры.

## 3. Ключевые определения (требуют утверждения)
- Устаревшая котировка: возраст последней цены > max_quote_age_ms.
- Резкое движение: изменение > X * ATR или > Y% за Z секунд.
- Быстрый возврат: возврат за уровень в пределах N свечей.
- Стабилизация рынка: спред ≤ max_spread, ликвидность ≥ min_liquidity,
  данные полные и свежие.
- Надёжный источник: из утверждённого whitelist.
- Подтверждение новости: официальное подтверждение ИЛИ ≥ 2 независимых
  источника.

## 4. Конечный автомат состояний
Состояния:
- НОРМА — торговля разрешена.
- УСТАРЕВШИЕ_ДАННЫЕ — новые входы запрещены.
- ПАУЗА_ГЕО — пауза из-за геополитики.
- ПАУЗА_ПУБЛИКАЦИЯ — пауза до/после важной публикации.
- ОЖИДАНИЕ_ПОДТВЕРЖДЕНИЯ — ждём реакции рынка после новости.
- ОЖИДАНИЕ_ЛОЖНОГО_ПРОБОЯ — ждём подтверждения пробоя.
- РУЧНОЕ_РАССМОТРЕНИЕ — требуется решение человека.
- ПРОВЕРКА_ВОССТАНОВЛЕНИЯ — проверка после восстановления.

Приоритет состояний (пример):
УСТАРЕВШИЕ_ДАННЫЕ > ПАУЗА_ГЕО > ПАУЗА_ПУБЛИКАЦИЯ >
ОЖИДАНИЕ_ЛОЖНОГО_ПРОБОЯ > ОЖИДАНИЕ_ПОДТВЕРЖДЕНИЯ >
ПРОВЕРКА_ВОССТАНОВЛЕНИЯ > НОРМА.

Новые входы разрешены только в состоянии НОРМА после всех проверок.

## 6. Правила для новых входов
1. Нет свежей цены — нет нового входа.
2. Сильная новость не отменяет правило устаревших данных.
3. Не входить по одному заголовку.
4. После публикации — сначала фактические данные и реакция цены.
5. Не входить на первом импульсе после новости.
6. Ждать закрытия свечи и удержания уровня.
7. При неясной структуре — пропуск сделки и уведомление.
8. Пропущенные данные нельзя считать непрерывным движением.
9. При неполном восстановлении данных входы остаются заблокированы.

## 7. Правила для открытых позиций
| Состояние | Действие |
|---|---|
| УСТАРЕВШИЕ_ДАННЫЕ | Проверить защитные ордера у брокера; critical-уведомление; стоп не считать гарантированным |
| ПАУЗА_ГЕО | Оценить изменение гипотезы; при ухудшении спреда/ликвидности — сократить/выйти по правилам |
| ПАУЗА_ПУБЛИКАЦИЯ | Защитные стопы действуют; после публикации — пересмотр позиции |
| ОЖИДАНИЕ_ЛОЖНОГО_ПРОБОЯ | Позиции по обычным правилам, если данные актуальны |
| РУЧНОЕ_РАССМОТРЕНИЕ | По умолчанию пауза сохраняется до решения человека |

Критерии досрочного выхода (задать явно):
- изменение исходной торговой гипотезы;
- спред > X;
- ликвидность < Y;
- устаревшие данные;
- геополитический риск выше уровня Z.

## 8. Уведомления и ручной режим
- Уровни: info / warning / critical.
- Каналы: лог, email, Telegram, вебхук.
- Кто может снять паузу вручную: __________.
- Таймаут ручного рассмотрения: manual_review_timeout_min.
- По умолчанию при отсутствии решения пауза сохраняется.
- Обязательные уведомления: сбой данных, восстановление данных,
  вход в паузу, выход из паузы, ручное вмешательство.

## 9. Аудит и логирование
Фиксировать: время, состояние, причина, источник события,
использованные параметры, принятое решение, результат.

## 10. Тестирование и приёмка
- Backtest и replay на исторических данных.
- Стресс-тесты: разрывы данных, ложные новости, расширение спреда.
- Paper trading перед запуском в live.
- Метрики: избежанные убыточные входы, пропущенные прибыльные входы,
  влияние на drawdown, slippage, время простоя.
